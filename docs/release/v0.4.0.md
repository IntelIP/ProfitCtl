# v0.4.0-rc.1 — system economics candidate

This PR prepares a versioned update. No public release, tag or production change
is implied. Releases remain maintainer actions from merged main.

## New behavior

- `system inspect`: local Python/configuration evidence with provider signals,
  hashes and explicit discovery limits; generated trees and symlinks excluded.
- `system evaluate`: strict `profitctl.system/v1` workload/service model,
  provenance, missing-input acquisition plan, per-service costs and margins.
- `system compare`: propagate declared driver changes and show affected service
  costs, changed assumptions and calculation dependencies.
- `system receipts`: summarize a sanitized Condere UsageReceipt export; preserve
  unreported/uncertain costs and omit arbitrary metadata.
- Modal official-domain registry support for the existing opt-in assessment.

Existing `simulate`, `compare`, `detect`, `assess`, ledger and four MCP tools keep
their interfaces. Python source collection is local-only; paid discovery is not
implicitly expanded to send source. Default unversioned Go builds still say
`dev`; candidate builds use `-ldflags="-X main.version=v0.4.0-rc.1"`.

## Smoke

```bash
go build -ldflags="-X main.version=v0.4.0-rc.1" -o /tmp/profitctl-v0.4.0 .
/tmp/profitctl-v0.4.0 version
/tmp/profitctl-v0.4.0 system compare examples/system/condere-synthetic-baseline.json examples/system/condere-synthetic-adverse.json
/tmp/profitctl-v0.4.0 system evaluate examples/system/condere-production.json
```

Expected version: `profitctl v0.4.0-rc.1`. Synthetic comparison: baseline $191.50,
adverse $276.50, delta +$85; these are artificial test values. Production template
returns valid JSON with incomplete status, null total/margin and exit 1.
Malformed input returns exit 2; output failure returns exit 3.

Local candidate smoke against Condere `32e9ec5` inspected 203 files, including
`pyproject.toml`, `Dockerfile.agentos` and the assessment workflow; generated
`.next` and `.venv` entries were absent. The production template surfaced 19
missing inputs. No provider calls or spend were required.

## Compatibility and limitations

The new JSON contract is additive. Reject unsupported versions and unknown
fields instead of silently approximating. Known zero and missing are distinct.
Source discovery is suggestive, not live topology. Causal links and rates must be
reviewed; no automatic capacity, quality, tier or autoscaler prediction. Synthetic
fixtures prove arithmetic, not production savings. Real usage collection and
recording remain PCTL-26/27. System CLI commands are available to local agents;
the private four-tool MCP contract has not gained a new tool.
