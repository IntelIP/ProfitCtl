# Design-Partner Qualification Criteria

Use this doc to decide whether a target should become an active evaluator.

## Required Criteria

A target qualifies when all of the following are true:

- they have a real pricing, packaging, or contract question
- the question affects recurring economics
- they can run a local install or Bun package install
- they can explain what decision they are trying to make
- they are willing to share enough input for calibration

## Strong Qualification Signals

The target is especially strong if they:

- are comparing tiered vs mix pricing
- are considering hybrid contracts or pilot-heavy deals
- need recurring-margin checks before shipping a pricing change
- have finance, product, or RevOps involved in the decision
- can make time for one follow-up loop

## Weak Qualification Signals

These are not necessarily disqualifiers, but they lower priority:

- the question is vague or exploratory only
- they want general financial planning help
- they need a hosted product before they can evaluate anything
- they cannot provide real inputs
- they only want a one-off answer and no follow-up

## Disqualifiers

Do not advance the target if they:

- do not have a concrete decision in motion
- cannot install the CLI or use Bun
- cannot give any real scenario inputs
- are asking for custom consulting instead of product evaluation
- need a collaboration platform before any comparison can happen

## Qualification Questions

Ask these in order:

1. What pricing or contract decision are you making?
2. Is the economics mostly recurring, one-time, or mixed?
3. Can you install `profitctl` locally or with Bun?
4. Can you share the smallest useful set of inputs?
5. Would you use this before committing to the decision?

## Outcome Labels

Use one of these labels after qualification:

- `qualified`
- `needs install help`
- `needs calibration`
- `needs follow-up`
- `not a fit`
