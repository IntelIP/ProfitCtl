# ProfitCtl Value Proposition

`ProfitCtl` helps teams compare pricing and contract shapes before they ship them.

## One-Line Positioning

> ProfitCtl models pricing, unit economics, and recurring-margin risk as code so teams can compare contract shapes before they commit.

## Who It Is For

Start with teams that already have a real pricing or contract decision in motion:

- B2B SaaS founders choosing between tiered, mix, or hybrid pricing
- product and finance leads checking recurring margin before packaging changes
- RevOps, sales, or CS teams defending pilot-heavy contracts
- teams that can share a small set of real inputs for calibration

## Who It Is Not For

Do not lead with ProfitCtl for users who want:

- generic personal finance planning
- a hosted collaboration suite first
- a billing system of record
- a vague simulator without a decision to make

## What To Say

Use this language in demos, intros, and outbound:

- "Compare one pricing shape against one realistic alternative before you commit."
- "See recurring margin and operating cost per user before you sign."
- "Use the output to decide whether a contract is safe to ship."

## What The User Gets

The first useful product motion is simple:

1. install `profitctl`
2. run one `compare`
3. review recurring margin, operating cost per user, and covenant health
4. calibrate the model with their real inputs
5. decide whether to change the pricing or contract shape

## Call-To-Action Path

When someone shows interest, send them through the same path every time:

1. install with the public release or Homebrew
2. open one benchmark pair that matches their problem
3. run `profitctl compare`
4. capture the minimum inputs needed to calibrate
5. agree on a follow-up if the result is decision-relevant

## Short Proof Statement

If the product is working, the evaluator should be able to answer this quickly:

> Which pricing or contract shape is easier to defend in steady state, and why?
