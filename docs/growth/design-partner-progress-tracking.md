# Design-Partner Progress Tracking

Track the pipeline in one place so weekly review can focus on movement, not memory.

## Weekly Metrics

Track these numbers every week:

- new targets added
- targets contacted
- replies received
- installs completed
- first compare runs completed
- calibration requests received
- design-partner commitments

## Target State Model

Use these states for each target:

- `targeted`
- `contacted`
- `replied`
- `qualified`
- `installed`
- `activated`
- `calibrated`
- `design partner`
- `closed`

## Minimum Tracker Fields

For each target, capture:

- company
- contact
- role
- score
- state
- decision question
- benchmark pair
- install path used
- activation date
- calibration date
- follow-up date
- blocker
- next action

## Weekly Review Questions

Each week, answer:

- Which benchmark pair got the clearest response?
- Where did the process stall most often?
- Was install friction the problem or was it positioning?
- Which metric did people trust first?
- Which targets should be replaced next week?

## Simple Review Output

End the weekly review with:

- one sentence on what improved
- one sentence on what blocked progress
- three targets to keep
- three targets to drop
- one thing to fix before the next outreach cycle

## Recommended Storage

Keep this tracker wherever the team already reviews execution.

Good options:

- Linear issue or project notes
- a shared doc
- a spreadsheet

The format matters less than keeping it current every week.
