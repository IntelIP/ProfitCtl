- Benchmark evidence: [`benchmark_scenarios/reports`](../../benchmark_scenarios/reports)

## Source Rules

1. Keep one active weekly dashboard.
2. Keep one active target list.
3. Keep one evaluator note per serious conversation.
4. Keep Linear as the source of work and next actions.
5. Keep benchmark reports as evidence, not as the operating record.

## What Each Artifact Owns

- `README.md`: navigation only
- `OPEN_SOURCE_COMPANY_PLAN.md`: company wedge, product system, open-core boundary, and 120-day plan
- growth docs: operating model, templates, and review guidance
- Linear: execution state, follow-ups, owners, and due dates
- benchmark reports: proof of product behavior
- release docs: distribution and install guidance

## What Not To Do

- do not treat multiple docs as parallel sources of truth
- do not store weekly metrics only in chat
- do not put execution state in benchmark reports
- do not use README text as the working tracker

## Weekly Maintenance Rule

If a metric, state, or owner changes during the week, update the active tracker first, then update the review template, then update the docs only if the operating model changed.
